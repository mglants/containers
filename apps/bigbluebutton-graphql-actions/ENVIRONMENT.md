# Container environment interface

The source-built images now configure themselves at startup. This follows the
community Docker images' environment-to-native-config approach, adapted to our
BBB 4.0 LiveKit stack. No host-side config generator is required by these images.
The ignored local fixture retains its own credentials, Compose inputs and test
certificates/provider settings under `.local-testing/`.

## Modes and precedence

- `BBB_CONFIG_MODE=env`: validate inputs and render native configuration.
- `BBB_CONFIG_MODE=file`: use mounted native configuration. Do not render over it.
- `BBB_CONFIG_MODE=auto` (default): render when `DOMAIN` or `BBB_PUBLIC_URL` is
  present; otherwise retain upstream/default file behavior. The frontend renders
  its standalone asset configuration from the same template when no public URL
  is supplied; explicit `env` mode still requires the public URL.

Generated configuration lives under `/tmp/bbb-config`, owned by the application
user, with directory mode 0700 and file mode 0600. Image config paths link there.
A writable `/tmp` is sufficient with a read-only root filesystem. Native config
mounts remain supported with `file` mode. Mixing mounted native files with `env`
mode is rejected; the mounted file is not overwritten.

Precedence is upstream defaults, generated environment settings, then optional
`BBB_CONFIG_JSON` deep overrides. Components with native env mappings (notably
Node `config` in signaling/webhooks) apply those native variables afterwards.
`BBB_CLIENT_CONFIG_JSON` independently overrides client settings served by apps.
Changing environment requires recreating a container/restarting a Kubernetes pod;
there is no live config reload.

Required application secrets are never generated by an entrypoint. Reuse them
across container replacement; missing required values fail startup without
printing their contents. Inputs are typed and escaped as properties, HOCON,
JSON/YAML or XML rather than substituted through shell/sed commands.

## Common settings

| Variable                                     | Meaning / default                                                                                                                                                          |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DOMAIN`                                     | Public hostname, optionally including a port; generates an HTTPS origin.                                                                                                   |
| `BBB_PUBLIC_URL`                             | Explicit HTTP(S) origin, including a custom port; takes precedence over DOMAIN. No path/query/credentials.                                                                 |
| `BBB_PUBLIC_SCHEME`                          | Scheme used with DOMAIN; default https.                                                                                                                                    |
| `SHARED_SECRET`                              | Persistent BBB API secret; required by web, apps, webhooks and recording workers.                                                                                          |
| `POSTGRES_HOST`, `POSTGRES_PORT`             | Database host/port; postgres / 5432.                                                                                                                                       |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`         | Application DB user/password; user defaults to bbb, password is required for apps/notes.                                                                                   |
| `POSTGRES_DATABASE`                          | apps defaults to bbb_graphql; notes defaults to blocknote_app.                                                                                                             |
| `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD` | Redis endpoint; redis / 6379 / no password.                                                                                                                                |
| `BBB_WEB_HOST`, `BBB_WEB_PORT`               | Internal web endpoint; web / 8090.                                                                                                                                         |
| `BBB_WEB_URL`                                | Explicit internal HTTP(S) web origin, overriding the host/port pair.                                                                                                       |
| `BBB_MIDDLEWARE_URL`                         | apps-to-middleware origin; http://middleware:8378.                                                                                                                         |
| `BBB_APPS_URL`                               | Middleware authentication origin; http://apps:8901.                                                                                                                        |
| `BBB_ACTIONS_URL`                            | Middleware actions origin; http://actions:8093.                                                                                                                            |
| `HASURA_WS_URL`                              | Middleware GraphQL endpoint; ws://hasura:8085/v1/graphql.                                                                                                                  |
| `BBB_CONFIG_JSON`                            | Optional JSON object for generated JSON/YAML/HOCON/properties roles; web uses a flat properties map. Nginx and native-only services use their documented settings instead. |
| `BBB_CLIENT_CONFIG_JSON`                     | Optional nested client settings override, consumed by apps.                                                                                                                |

For secret files, supported names accept an additional `_FILE` suffix:
`SHARED_SECRET`, `POSTGRES_PASSWORD`, `REDIS_PASSWORD`, `LIVEKIT_KEY`,
`LIVEKIT_SECRET`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, `GLADIA_API_KEY`,
`TURN_SECRET`, `TURN_EXT_SECRET`, `PGPASSWORD`, `HASURA_SECRET`,
`HASURA_GRAPHQL_ADMIN_SECRET`, `DATABASE_URL`, `SECRET_KEY_BASE`, `SMTP_PASSWORD`,
`OPENID_CONNECT_CLIENT_SECRET`, `BBB_CONFIG_JSON` and `BBB_CLIENT_CONFIG_JSON`.
This applies to our adapter-equipped images. Upstream images retain their own
native interfaces. The secret file must be readable by the runtime UID. Set
exactly one of NAME and NAME_FILE; supplying both fails. A terminal line ending
is removed, while leading/trailing spaces in the value are preserved.

### TURN/STUN

Web renders the upstream Spring TURN/STUN configuration from `STUN_SERVER`,
`TURN_SERVER`, `TURN_SECRET`, `TURN_EXT_SERVER`, `TURN_EXT_SECRET` and `TURN_TTL`
(86400). With TURN_SECRET set, TURN_SERVER defaults to turn:DOMAIN:3478, using
the hostname rather than the web port. An external TURN URI requires its secret.
Specify TCP/TLS/custom ports in the URI, e.g.
`TURN_EXT_SERVER=turns:turn.example.test:5349?transport=tcp`.
There are no implicit public STUN services or generated TURN credentials.

### Frontend

The frontend extracts the reviewed BBB route snippets from pinned upstream source
during its build, with checked address/storage adaptations, and generates a full
routing config from env. `BBB_HTTP_PORT` defaults to 8080. HTTPS may terminate at
a gateway: the public URL still controls forwarded scheme and browser URLs.
For in-container TLS set both `BBB_TLS_CERT_FILE` and `BBB_TLS_KEY_FILE`;
`BBB_TLS_PORT` defaults to 8443. These are file **paths**, not secret-file aliases.

Upstream host/port overrides use `BBB_<SERVICE>_HOST/PORT`, where SERVICE is WEB,
MIDDLEWARE, HASURA, NOTES, SIGNALING, LIVEKIT, PLUGINS or WEBHOOKS. Defaults are
Compose service names and their existing ports. DNS_RESOLVER defaults to the
nameserver in the container's resolv.conf, so Docker DNS is not baked into the
image. Shared published/presentation storage is mounted read-only at
`/presentations`, preserving the player's assets packaged in the image.

`BBB_LANDING_FILE` optionally serves a custom root launcher. The local fixture's
separate Greenlight HTTPS listener uses GREENLIGHT_PUBLIC_URL,
GREENLIGHT_TLS_PORT (8444), and BBB_GREENLIGHT_HOST/PORT (greenlight/3000).
A normal gateway deployment can route Greenlight directly to its own service.

Greenlight, Hasura and PostgreSQL use their official environment interfaces.
LiveKit's official image accepts `LIVEKIT_CONFIG` (YAML as an environment value);
the local fixture uses it instead of a mounted config file.

## Community comparison and sources

Preserved common community names include DOMAIN, SHARED_SECRET,
POSTGRES_PASSWORD, ENABLE_RECORDING, ENABLE_LEARNING_DASHBOARD, WELCOME_MESSAGE,
WELCOME_FOOTER, STUN_SERVER, TURN_SECRET and TURN_EXT_SERVER/SECRET. This is an
interface for our BBB 4.0 LiveKit images, not a drop-in implementation of the
community stack's legacy FreeSWITCH/Mediasoup/HAProxy switches.

Research was checked against the pinned community reference and locked BBB 4.0
sources, including native env maps and config parsers:

## Validation

The Dockerfile runs the Go renderer tests while building the shared adapter.
`ci/goss.yaml` checks each published component and non-root execution. Stable-release
discovery tests remain in `tests/`. The ignored `.local-testing/` fixtures add
read-only filesystem, secret-file, authenticated Redis and full local-stack checks.
